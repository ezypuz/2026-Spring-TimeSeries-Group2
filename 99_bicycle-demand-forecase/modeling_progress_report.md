## 3. SARIMA / ARIMAX 모델링 (`bicycle_forecast_weekday.ipynb`)

### 3-1. 설정값

| 항목 | 값 |
|------|----|
| 계절 주기 | S = 24 (시간 단위, 일 주기) |
| Test set | 마지막 30일 |
| 외생변수 | 기온 (℃) — `*_weather.csv` |
| 차분 | D = 1 (계절 차분), d = 0 (ADF 기준) |

### 3-2. 차수 선택

`auto_arima` (pmdarima, AIC 기준)를 시도하였으나 메모리 제약으로 완전 탐색이 불가하였다. 탐색이 끊기기 전까지의 결과 중 AIC가 가장 낮은 차수를 채택하였으며, ACF/PACF 시각화 결과와 비교하여 수동으로 최종 확정하였다.

**최종 채택 차수**: `ARIMA(2,0,1) × (1,1,0,24)`

### 3-3. 잔차 진단

| 검정 | 귀무가설 | 결과 |
|------|----------|------|
| Ljung-Box (Prob(Q) = 0.99) | 잔차에 자기상관 없음 (백색잡음) | ✅ 기각 불가 → 백색잡음 |
| Jarque-Bera (Prob(JB) = 0.00) | 잔차가 정규분포를 따름 | ❌ 기각 → 정규성 없음 |

잔차의 자기상관은 존재하지 않으나 정규성은 기각되었다 (Kurtosis = 5.89). 이는 잔차 분포가 정규분포보다 두꺼운 꼬리(leptokurtic)를 가짐을 의미한다. 정규성 위반의 주된 원인으로는 **데이터의 zero-inflation**을 들 수 있다. 따릉이 대여량은 심야·새벽 시간대에 0이 집중적으로 발생하는 구조적 특성이 있어, 잔차 분포가 대칭적인 정규분포를 따르기 어렵다. 시계열 예측 모델에서 이러한 정규성 위반은 흔히 관찰되며, 자기상관이 없다는 점에서 모델이 시계열 구조는 충분히 포착하였다고 볼 수 있다.

### 3-4. 평가 지표

| 지표 | 설명 |
|------|------|
| RMSE | 기본 예측 정확도 |
| MAE | 이상치 영향 적음 |
| Asymmetric RMSE (α=2) | 과소예측에 α배 패널티 → 주요 지표 |
| 과소예측 비율 | 자전거 고갈 위험도 |

비대칭 손실함수:

$$L(\hat{y}, y) = \begin{cases} \alpha \cdot (\hat{y} - y)^2 & \hat{y} < y \text{ (과소예측)} \\ (\hat{y} - y)^2 & \hat{y} \geq y \text{ (과대예측)} \end{cases}$$

## 4. ML 모델링 (`bicycle_ml.ipynb`)

### 4-1. 결측치 처리 — SARIMA와의 차이

ML 노트북은 SARIMA 노트북과 결측치 처리 방식이 다르다. SARIMA에서는 장기 결측 구간을 NaN으로 유지하고 학습 윈도우에서 제외하였으나, ML 노트북에서는 `limit` 제한 없이 선형 보간 → 요일+시간 평균 대체를 순차적으로 적용하여 **장기 결측 구간(최대 36일)도 보간된 값으로 학습에 포함**된다.

### 4-2. Feature Engineering

SARIMA와 달리 ML 모델은 시계열 구조를 자동으로 학습하지 못하므로 피처를 직접 구성하였다.

| Feature | 설명 |
|---------|------|
| hour, dayofweek, month | 시간 구조 (일/주/연간 계절성) |
| is_weekend | 주말 여부 |
| lag_1, lag_24, lag_168 | 1시간 / 1일 / 1주 전 수요 |
| rolling_mean_24, rolling_mean_168 | 최근 24시간 / 168시간 평균 |
| temp | 기온 (외생변수) |

### 4-2. 모델 구성

| 모델 | 설명 |
|------|------|
| Random Forest | 트리 앙상블, feature importance 해석 가능 |
| XGBoost (표준) | Gradient Boosting, RF 대비 성능 우수 경향 |
| XGBoost (비대칭 손실, α=2,3,5) | Custom objective로 over-prediction에 비해 under-prediction에 α배 패널티 |

비대칭 손실 XGBoost의 custom objective:

```python
def asymmetric_obj(y_pred, dtrain, alpha=2.0):
    y_true = dtrain.get_label()
    errors = y_pred - y_true
    grad = np.where(errors < 0, alpha * 2 * errors, 2 * errors)
    hess = np.where(errors < 0, alpha * 2 * np.ones_like(errors), 2 * np.ones_like(errors))
    return grad, hess
```

### 4-4. 전체 모델 비교 결과 (정류소 02128 기준)

| 모델 | RMSE | MAE | Asym.RMSE (α=2.0) | Under-pred rate (%) |
|------|------|-----|-------------------|----------------------|
| SARIMA | 0.640 | 0.524 | 0.750 | 26.2 |
| ARIMAX | 0.599 | 0.455 | 0.790 | 46.2 |
| Random Forest | 0.601 | 0.483 | 0.762 | 27.9 |
| XGBoost | 0.599 | 0.480 | 0.763 | 27.9 |
| XGBoost (α=2.0) | 0.650 | 0.549 | 0.761 | 26.4 |

![Model Performance Comparison](model_comparison_chart.png)

RMSE/MAE 기준으로는 ARIMAX와 XGBoost가 유사하게 우수하나, ARIMAX는 under-prediction rate가 46.2%로 매우 높아 자전거 고갈 위험 측면에서 불리하다. 주요 평가 지표인 Asym.RMSE 기준으로는 모델 간 차이가 크지 않으나, XGBoost (α=2.0)가 under-prediction rate를 26.4%로 낮추면서 Asym.RMSE도 가장 낮아 균형 잡힌 성능을 보인다.

## 5. 논의 필요 사항

> 아래는 팀 전체가 방향을 확정해야 할 이슈들이다. 의견 부탁한다.

---

### 🔴 Issue 1. `auto_arima` 메모리 한계 → 차수 선택 신뢰성 문제

`auto_arima`는 AIC 기준으로 차수를 탐색하는데, 5년치 시간 단위 데이터(~43,800시간)를 S=24로 탐색하면 메모리가 부족하여 중간에 끊겼다. 끊기기 전까지 탐색된 모델 중 AIC가 가장 낮은 차수를 채택하였으므로, 전역 최적이라는 보장이 없다.

**제안**: 2023년 이후 데이터만 사용하는 것도 고려할 수 있다 (약 2년치 → ~17,520시간). 데이터가 줄어드는 대신 `auto_arima` 완전 탐색이 가능해지고, 최근 수요 패턴이 더 잘 반영될 수 있다. 다만 2021~2022년 데이터를 버리는 트레이드오프가 있다. **어떻게 생각하나?**

---

### 🟡 Issue 2. 평일/주말 분리 — 계획서에 없던 변경

현재 노트북에서 평일(`dayofweek < 5`)과 주말(`dayofweek >= 5`)을 분리하여 별도 모델을 적합하고 있다. 계획서에는 이 분리가 명시되지 않았다.

**분리의 근거**: 따릉이 이용 패턴은 평일(통근·통학 중심)과 주말(여가 중심)이 구조적으로 다를 가능성이 높으며, 이를 하나의 모델로 학습하면 두 패턴이 서로 간섭하여 예측 정확도가 낮아질 수 있다.

**논의 필요**: 이 분리 전략을 보고서에서 방법론적 선택으로 정당화할지, 아니면 단일 모델로 통합할지 의견 부탁한다.

---

### 🟡 Issue 3. 23개 정류소를 각각 따로 돌리는 구조 — 목적과 맞나?

현재는 `TARGET_RENT_ID`를 바꿔가며 동일한 모델을 23번 반복 적합하는 구조다. 그런데 원래 프로젝트 목적을 다시 생각해보면, 단순히 "각 정류소의 수요를 예측"하는 것을 넘어서 **정류소 간 자전거 재배치(rebalancing) 최적화**를 원하는 것 아니었나?

23개를 독립적으로 돌리면 할 수 있는 것:
- 정류소별 수요 예측값 → 피크 타임 파악
- 어느 정류소가 언제 고갈 위험이 높은지 식별

그러나 이것만으로는 "A 정류소에서 B 정류소로 언제 얼마나 이동시켜야 하는가"는 답하기 어렵다. 그걸 하려면 정류소 간 수요 불균형(surplus vs. deficit)을 동시에 모델링하거나, 예측값을 바탕으로 별도의 rebalancing 로직이 필요하다.

**논의 필요**: 23개 독립 예측으로 마무리할지, 아니면 예측 결과를 활용한 간단한 rebalancing 분석(예: 잉여/부족 정류소 매핑)을 추가할지 결정이 필요하다.

---

### 🟠 Issue 4. 수요 censoring 문제 — 고질적 한계, 보고서에 명시 예정

이건 해결보다는 한계로 명시하기로 정리됐다. 보고서 limitation 섹션에 아래 문구를 포함할 예정이다.

> "본 연구는 실현된 대여량을 수요의 proxy로 사용하였으나, 스테이션 재고 부족 시 관측 수요는 실제 수요보다 낮게 기록되는 censoring 문제가 존재하며, 이를 무시할 경우 서비스 수준이 과대추정될 수 있다. 재고 데이터가 없는 본 연구의 한계상 이를 보정하지 못하였으며, 비대칭 손실함수(asymmetric loss)를 통해 under-prediction에 패널티를 부과함으로써 부분적으로 이를 완화하였다."

참고로 선행 연구에서도 이 문제는 공통적으로 지적되며, 정교한 보정을 위해서는 스테이션별 실시간 재고 데이터가 필요하나 따릉이 공개 데이터에는 포함되어 있지 않다.
